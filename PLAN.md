# Cityverse — учебный проект по смарт-контрактам

Документ фиксирует план и принятые решения. По мере работы обновляем.

## Цель

Изучить программирование смарт-контрактов на практике, построив играбельный MVP игры, в которой ключевые места реального города токенизированы как NFT и ими можно владеть, торговать, прокачивать.

## Игровая концепция (гибрид)

Сочетает экономику, конфликт и социальный крючок. Базовая петля. Пометки `[MVP]` / `[v2]`
показывают, что входит в первый играбельный срез, а что отложено.

### Сущности

- **Place** — NFT (ERC-721), уникальное место города. Фиксированное предложение (50–100 мест на старте) → создаёт дефицит. `[MVP]`
- **$CITY** — внутриигровой токен (ERC-20). Им платят за апгрейды, выкупы, выдают как награды. `[MVP]`
- **Категории мест:** `landmark` / `transit` / `food` / `park` — у каждой свой базовый yield rate. `[MVP]`

### Петля игрока

1. **Владение.** Купил Place — он пассивно копит $CITY (yield по времени). Клеймишь когда удобно. `[MVP]`
2. **Конфликт.** Любое место можно **forced buyout** (механика Harberger Tax): оффер по эскалирующей цене. Хочешь держать редкий ландмарк — плати «налог» или потеряешь. `[MVP]` — это «фишка» игры, ради неё терпим сложность escrow/reentrancy.
3. **Активность.** Другие игроки делают чек-ин в твоём месте (геолокация off-chain, подпись верифицируется on-chain) → краткосрочный буст yield. `[v2]`
4. **Прогрессия.** Апгрейды места за $CITY повышают потолок yield. `[v2]`
5. **Сеты.** Владеешь всеми местами района → district bonus к yield. `[v2]`

### Что это даёт для обучения

- ERC-721 (NFT) и ERC-20 (фунгибл-токены).
- Time-based yield, тесты с манипуляцией времени.
- Маркетплейс, аукцион, защита от reentrancy.
- AccessControl, роли (MINTER и т.п.).
- EIP-712 подписи и граница on-chain / off-chain (в v2).
- Storage layout и базовая газ-оптимизация.

## Стратегия сборки: walking skeleton

Главное изменение относительно «фронт в самом конце»: **тонкий фронт появляется рано**
и наращивается вместе с контрактами. Так интеграция проверяется по чуть-чуть, а не «большим
взрывом» в финале, и раньше виден результат на экране.

- После Фаз 1–2 поднимаем минимальную страницу, которая **читает** state с чейна (мои Place, баланс $CITY).
- Каждая следующая фаза контрактов сразу получает тонкий слой UI (claim, buy, forced buyout).
- Красота карты/дизайн — в последнюю очередь; сначала «живое и кривое», потом «красивое».

## Объём MVP (что режем осознанно)

**Первый играбельный билд = Фазы 0–4 + тонкий фронт + деплой.**

Входит в MVP:
- Place NFT (владение местами).
- $CITY токен.
- Yield (владеешь → капает валюта, claim по времени).
- Forced buyout (Harberger-style) — конфликт-механика.
- Тонкий фронт поверх всего этого.
- Деплой в публичный тестнет, играем с друзьями.

Отложено в **v2** (после первого играбельного билда):
- Апгрейды мест.
- District bonuses (сеты районов).
- Чек-ины через EIP-712 + off-chain Node-сервис (самый сложный кусок, не в ядре).

## Структура репозитория (монорепо)

Один репозиторий, папки внутри. Причина: контракты и фронт жёстко связаны (фронту нужны ABI и
адреса задеплоенных контрактов) — в монорепо они всегда в синхроне, история одна, для портфолио нагляднее.

```
cityverse/
├── contracts/      # Foundry-проект: forge init сюда (src/, test/, lib/, foundry.toml)
├── web/            # Next.js + wagmi + viem + карта (walking skeleton, появляется рано)
├── signer/         # Node-сервис для чек-инов (v2, позже)
├── PLAN.md
├── README.md
├── .gitignore      # ставим ДО первого git add
└── .env.example    # список переменных без значений
```

Нюанс тулинга: Foundry тянет зависимости git-сабмодулями в свою `lib/`, поэтому `forge init`
запускаем **внутри `contracts/`**, чтобы сабмодули не засоряли корень. Менеджер воркспейсов
(pnpm/npm workspaces) на старте не нужен — две независимые папки со своим тулингом проще.

## Решения, уже принятые

- **Геймплей:** гибрид (экономика + захват + социалка) — петля выше.
- **Тулинг:** Foundry.
- **Глубина проекта:** полноценный играбельный MVP (контракты + фронт + деплой).
- **Структура:** один монорепо, фронт растёт walking-skeleton’ом с ранних фаз.
- **Скоуп MVP:** Фазы 0–4 + тонкий фронт; апгрейды/районы/чек-ины → v2.
- **Репозиторий:** публичный на GitHub, имя `cityverse`, создаётся через `gh repo create`.

## Правила безопасности (с самого первого коммита)

В блокчейн-разработке утечка приватного ключа = реальные потерянные деньги. Боты сканируют GitHub в реальном времени, поэтому исправлять «потом» поздно — секрет уже в истории.

- **Никогда** не коммитить: `.env`, `*.key`, `mnemonic.txt`, `keystore/*`, любые приватные ключи.
- Хранить приватный ключ только в `.env` локально или, лучше, в Foundry keystore (зашифрованный, с паролем).
- Для разработки использовать **отдельный кошелёк** только с тестовыми токенами. Не основной кошелёк.
- `.gitignore` ставим **до** первого `git add .`.
- `.env.example` — да, со списком переменных, но без значений.
